# 性能と制限

Universe Mapは最新デスクトップで60 FPS、モバイルで30 FPSを目標とします。利用可能な
点をすべて同時表示することより、安定したフレーム時間を優先します。

## 描画負荷を制限する仕組み

- 恒星、系外惑星の主星、銀河群、大規模構造はGPUの点・線バッチを使います。
- 大型カタログの各レコードに個別Three.jsオブジェクトを作りません。
- カメラ連動の空間インデックスが必要な恒星・銀河タイルだけ読み込みます。
- 詳細テクスチャとマテリアルは有効なLOD付近で読み込みます。
- 軌道計算の更新頻度を下げ、状態間を補間します。
- ラベルはスケール、品質、衝突に応じた予算を守ります。
- ボリューム効果は品質別のレイマーチとピクセル予算を使います。
- レンダーループはAngularの変更検出外で実行します。

## グラフィックプロファイル

| プロファイル | 用途                                 | 主な削減                                         |
| ------------ | ------------------------------------ | ------------------------------------------------ |
| 低           | スマートフォン、古いノートPC、省電力 | 点、テクスチャ、ボリュームサンプル、タイルを削減 |
| 中           | 内蔵GPUと一般利用                    | 密度とポスト処理を均衡                           |
| 高           | 最近のデスクトップ                   | より豊かなカタログ、テクスチャ、ボリューム、詳細 |

プロファイルは科学座標を変更しません。

## 実機測定の状況

2026年8月27日の反復測定では、Apple M5 Max搭載の高性能MacBook Pro、macOS 26.6、Chrome 151、
実際のMetalレンダラー、デスクトップ/高品質、デバイスピクセル比1を使用しました。3回の測定で、最初の
操作可能な地図の中央値は259.3 ms、Tempelの最初の可視フレームの中央値は7.1 msでした。3回のコールド
遷移はp95 9.1–9.2 ms、p99 16.7 ms、最大66.6–75 ms、長いフレーム0.24–0.36%でした。3回の
ウォームアップ後の3サイクルは100ジオメトリ、18テクスチャ、44ドローコールを維持し、回収後のヒープは
0.77 MiB減少しました。

別の観測プラネタリウム測定では、1440 × 900 CSSピクセルでブラウザーDPR 2を指定しました。高品質
レンダラーは文書化済みのDPR上限1.5を適用し、3回ともそこで安定しました。各回は1452–1455フレームを
記録し、p95 9.1 ms、p99 9.3 ms、最大9.4–9.5 ms、長いフレーム0件でした。木星は3回すべてで
解像表示へ移行しました。

同じ実機上で明示的にシミュレーションとしたストレス行列も予算内でした。中品質、Chrome CPU 4×低速化、
Canvas DPR 1.25では、中央値がp95 9.3 ms、p99 16.7 ms、最大24.9 msで、長いフレームは0件でした。
低品質、CPU 6×、DPR 1では、中央値がp95 15.9 ms、p99 25.1 ms、最大42 ms、最悪49.9 ms、
長いフレーム0.20–0.34%でした。木星はストレス下の6回すべてで解像表示になりました。GPUはM5 Maxの
ままなので、これは回帰余力の測定であり、中・低性能を代表する実機の証拠ではありません。

起動、Tempel、リソース、スケール間フレーム、観測プラネタリウムの5つの性能ベンチマークは、
`UNIVERSE_BENCHMARK_REPORT_PATH`で同じバージョン付きJSON証拠レポートを出力できます。Gitリビジョンと
dirty状態、ホスト特性、ブラウザーとWebGLレンダラー、設定、サンプル、要約を記録します。
`UNIVERSE_BENCHMARK_REQUIRE_PHYSICAL=1`はCPU低速化、ソフトウェアレンダリング、または宣言済みの
`UNIVERSE_BENCHMARK_DEVICE_CLASS`がない測定をレポート書き込み前に拒否するため、シミュレーションが
実機行列へ暗黙に混入しません。

`npm run benchmark:campaign`は、代表実機1台で5つのプロトコルを順番に実行します。クリーンなGit
チェックアウトと宣言済みのクラス・ラベルを必須とし、CPU低速化を無効化し、厳格な予算と最低3回の
反復を適用し、既定ではクラスに対応する品質を使います。5つのレポートをリポジトリ外へ書き出し、
SHA-256ダイジェストで結ぶ`universe-map/performance-campaign@1`マニフェストを生成します。このコマンドは
比較可能な証拠をまとめるもので、1台の実機を別クラスとして扱うものではありません。

`npm run benchmark:campaign:simulated`は代表機器がない場合の、同一ホスト上の独立したストレス
キャンペーンです。ChromeのCPU低速化を5プロトコルすべてに適用し、中品質を4×・観測DPR 1.25、
低品質を6×・DPR 1で実行します。10ベンチマークは順番に実行され、クリーンなチェックアウトから
SHA-256と明示的な制約を持つ`universe-map/simulated-performance-campaign@1`マニフェストを生成します。
元ホストのGPU、グラフィックスメモリ、ドライバー、メモリ帯域、熱特性は再現されません。中・低は
回帰検出用プロキシであり、実機証拠ではありません。予算超過が後続プロトコルを止めることはなく、
完全なマニフェストが各プロトコル、プロファイル、キャンペーンを`withinBudget`で記録した後に、厳格
モードが失敗を返します。既知の回帰ベースラインを意図的に収集する場合に限り、
`UNIVERSE_BENCHMARK_STRICT=0`を使用します。

反復実機ベースラインが裏付けるのは引き続き高性能クラスだけです。中・低性能実機の測定は、機器が
ない場合のブロッカーではなく、将来の任意の照合です。

## デバッグパネル

URLに`?debug=true`を加えると、FPS、ドローコール、三角形、ジオメトリ、テクスチャ、
可視天体、座標系、カメラ距離、ターゲット、ユリウス日、品質を表示します。

```text
https://super-universe.app/ja/?debug=true
```

JavaScript、WebGL 2、選択品質に十分なGPUメモリ、ポインターイベントが必要です。
カタログは全恒星・銀河を網羅せず、半径とスケール遷移は一部適応されます。受信した光は、ガリレオ衛星、
簡略衛星、準惑星、小惑星、彗星を含む対応太陽系天体とHYG恒星の光行時間を補正します。文書化された
系外惑星系は公開された主星距離から得た遅延を共有しますが、局所惑星位相は説明用のままで、距離未公開の
系は同時刻を維持します。近傍銀河は幾何学的カタログ光行時間を使い、Cosmicflows-4と大規模構造は光度距離
または共動距離から推定したΛCDMルックバック時間を使います。位置、形状、測定値は静的なままです。宇宙論サーベイの範囲も異なります。
未検出は物理的ボイドの証明ではなく、詳細な惑星表面、ライブ気象、厳密な相対論的
レイトレーシングは対象外です。

遅い場合は品質を下げ、GPUを使う他タブを閉じ、既知のターゲットへ戻ります。静的
データに失敗した場合はネットワークパネルで該当ファイルを確認してください。
