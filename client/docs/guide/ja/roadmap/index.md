# ロードマップ

_最終確認：2026年9月10日。_

このページはUniverse Mapの正式な公開ロードマップです。固定したリリース日を約束するのではなく、
成果と検証条件を示します。科学的精度、読みやすいナビゲーション、安定したフレーム時間、完全に
静的なブラウザー構成は、すべての項目に共通する制約です。

## ステータスの読み方

| 状態     | 意味                                                         |
| -------- | ------------------------------------------------------------ |
| 提供済み | 現在のアプリで利用でき、自動テストで保護されている           |
| 現在     | 既存の体験に対して次に改善する項目                           |
| 次       | 科学的な契約または実機測定を先に必要とする作業               |
| 延期     | 新しい出典・データ・高密度カタログがある場合にだけ有効な作業 |

## 提供済み

- **地球観測者プラネタリウム**では、自由に見回せるHYG恒星10,000個、現代星座、高度と方位角、
  ポインターに固定される102°〜2°の視野角、URLから復元できる461地点、同意後に小数第3位へ
  丸めるブラウザー位置情報、説明用の地域シーンを利用できます。
- プラネタリウムから3D地図へは同じレンダラー上で2.4秒かけて戻り、最初の視線を保って
  地球を回転中心にします。この説明用アニメーションは入力で直ちに中断し、動きを減らす設定を尊重します。
- カード・検索・プランナー・時刻バーは幅の狭い画面や高さの低い画面に対応し、折りたたみと
  展開表示を使えます。閉じる操作は見出し、軌道操作は軌道情報の横に置きます。重複するオレンジの
  通知は取り除き、科学的説明は残します。ホイールテストは慣性の停止と距離下限での新しい操作を
  検証し、カメラ制御自体は変更しません。
- 必要時だけ動く地域観測プランナーは、見える月・惑星・カタログ衛星を高度順に並べ、カタログで最も
  明るい48恒星から見える恒星を最大8個提案します。提案を選ぶと既存の天体詳細を開き、空をその方向へ
  向けます。計算した地平線と利用可能な地形遮蔽を反映します。現在の対象には、出・南中・没、USNO薄明帯、
  月光干渉、明示的に説明用の最適時間指数を含む24時間高度曲線が加わり、操作で共有時刻とカメラを同時に
  移動できます。曲線の対象は同じローカルカタログから変更でき、そのプレビュー中は現在の空を動かしません。
  対象・共有時刻・カメラを確定するのはこの操作だけです。同じ計算で連続する7夜を比較し、100点満点の
  比較可能な説明用指数で最適な夜を自動的に強調します。高度、空の暗さ、月光、地形からの余裕を表示し、
  直接操作で5分刻みに局所再計算した最適時刻へ移動します。現在の天気、光害、未測量の地域障害物はモデル外です。
- 固定カタログ地点ごとに、権威あるNOAA/NCEI ETOPO 2022 v1 60秒角表面地形から計算した
  360°遮蔽プロファイルがあります。小さなプロファイルは必要時だけ読み込まれ、モデル地形の背後に
  ある恒星・月・惑星・衛星を隠します。建物、植生、微地形、自由座標地点はこのモデルの対象外です。
  計算された3つの距離層（0～30、30～100、100～300 km）がシルエットに奥行きを与え、色と照明は
  スタイル表現です。
- 月、見える7惑星、カタログ収録の他20衛星は、既存のThree.jsオブジェクト、マテリアル、照明、
  遅延テクスチャを再利用します。観測地点からの方向と角直径には物理軌道距離を使います。ガリレオ衛星の
  位置は計算値、J2000平均要素による他16軌道は外挿と明記します。衛星は視野角12°以下、または直接
  選択された場合に表示し、広角時の重なりを防ぎます。読みやすさの最小サイズは説明用です。
- 銀河系の外観と内部通過は同じ固定銀河中心座標の点群を使い、銀河画像やカメラ沿いのトンネルは
  使いません。円盤と太陽は、円盤直径10万光年、太陽の銀心距離8.178 kpcという共通の基準尺度を
  使います。カメラ経路とホイール感度は変えません。微細な粒は遠近法による視差を示し、追加の
  有界GPUバッチが近距離詳細を補います。金色の棒、象牙色の核、青白い腕、暗い塵の帯は説明用の
  密度と色であり、個々のGaia測定やブラックホールの放射ではありません。
- 局所座標系は非表示のまま3,600〜2,400シーン単位で展開します。HYG/Gaiaは座標が固定された後、
  900〜90単位で現れます。銀河点群は220〜70単位で消え、惑星と軌道は240〜90単位で現れます。
  近距離詳細は停止時も逆方向に戻るときも同じ場所を保ちます。
- 外部銀河も渦巻・楕円・不規則の密度を持つ固定点群で描き、複数方向から表示できます。
  カタログ位置は維持しますが、内部点と色は説明用です。選択時には情報カードと操作を保ち、
  巨大な惑星用選択リングを点群に重ねません。
- Gaia DR3階層は、品質条件を満たす2,923,790件を、恒星近傍の概要用に遠方の計算済み512 pc集約と
  133,526件の実測出典サンプルで表現します。詳細化した各512 pcリーフは、最も明るい32件と決定論的な
  一様選択を合わせて最大96点を保持します。視野と品質で制限した詳細化は見える枝だけを読み込み、
  モジュールWorkerで検証し、型付き配列をコピーなしで転送します。各出典にThree.jsオブジェクトは
  作りません。保持されたGaiaサンプルは出典IDを維持し、共有GPUバッチから直接選択・フォーカスできます。
  情報カードには実測G、BP−RPと、視差の逆数から計算した距離を表示します。グローバル検索とラベルには
  含めず、集約セルは匿名のままです。サンプル領域は不完全です。ズームアウト時には詳細サンプルが
  計算済みルートへ滑らかに移行し、ローカルグループ
  まで控えめに残ります。同時に局所体積は対数スケールで銀河系円盤へ溶け込みます。
- HYGのJ2000直交速度により、共有恒星カタログ、観測者の空、星座図形を時間伝播します。
  信頼度は外挿と明示し、有効範囲は±10,000ユリウス年に制限します。
- 時間モード**受信した光**は、選択日時を受信日時として扱うようになりました。Astronomy Engineで
  地球から見た太陽、月、惑星を遡及計算し、太陽系重心から各HYG恒星固有の遅延日時を解きます。
  対応する自転はその放射日時を使い、天体カードに遅延と放射日時を表示し、HYGモデルは明示した
  ±10,000ユリウス年の制限を維持します。
- ガリレオ衛星は、地球に届いた時刻のAstronomy Engineを使います。その他の公開軌道要素を持つ衛星、
  準惑星、小惑星、彗星は、既存のJPL二体要素で幾何学的光行時を反復計算します。信頼度は外挿のままで、
  表示用の距離強調は科学計算に含みません。
- 文書化された系外惑星系は、NASAが公開した主星距離から得た太陽系重心基準の遅延を共有します。主星の
  静的方向は変えず、局所惑星軌道をその放射日時で評価しますが、位相は説明用と明記します。距離未公開の
  系は同時刻のままです。
- 近傍銀河はカタログ距離の幾何学的光行時間を使うようになりました。Cosmicflows-4の距離モジュラスは
  光度距離、大規模構造の地図距離は共動距離として扱い、両者を文書化済みの平坦ΛCDMモデルで逆算します。
  天体カードは推定赤方偏移とルックバック時間を示し、位置と静的外観は変えず、結果を外挿と明記します。
- 公開された壁、確率的な引力圏、アトラクター、リペラーはTempelフィラメント網と統合せず、個別の
  出典と記号を保持します。
- コールドスタート、Tempel遷移、リソース安定性、フレーム安定性には再現可能なブラウザー
  ベンチマークがあります。
- 実際のMetalレンダラーを使うApple M5 Maxで、起動、Tempel、コールドフレームを各3回、
  ウォームアップ後のリソースを3サイクル記録する高性能実機の反復ベースラインを完了しました。
  別の機器クラスの根拠としては扱いません。
- 観測プラネタリウム専用ベンチマークで、実際の空のパン、再中央揃え、木星をアンカーに共有の
  解像惑星表示へ移るズーム、ズームアウトを対象にしました。高性能Retina実機で3回実行し、高品質の
  DPR上限1.5で長いフレームなしに合格しました。別の明示的なシミュレーションCPU 4×/6×ストレス行列も
  合格し、回帰余力だけを測定します。
- 5つの手動性能プロトコルが、ソース状態、ホスト、レンダラー、設定、サンプル、要約を記録する同じ
  バージョン付きJSON証拠レポートを共有するようになりました。実機専用ガードは、シミュレーション、
  ソフトウェア描画、または未分類の測定をレポート書き込み前に拒否します。クリーンなチェックアウトを
  必須とするキャンペーン実行器が順番に測定し、5ファイルをSHA-256検証可能なマニフェストへ結びます。
- 別のクリーンチェックアウト用コマンドが、5プロトコルすべてについて同一ホスト上の中・低回帰
  キャンペーンを実行します。中品質はCPU 4×、低品質はCPU 6×です。独立したシミュレーション
  マニフェストが10レポートを結び、GPU、メモリ、ドライバー、帯域、熱特性は元ホストのままだと明記します。
- 4つの補完カタログは専用のモジュールWorkerで取得・デコードされ、型付き配列バッファーをコピーなしで
  転送します。準備中はシーン資源を作らず、完了後にメインスレッドのレジストリ、検索、ジオメトリ、
  GPUを導入するには、新たに1.2秒のカメラ安定時間が必要です。遷移は待機時間をリセットし、観測モードは
  バックグラウンド導入を完全に停止します。明示的な対象は従来どおり直ちに読み込みます。リビジョン単位の
  クリーンなキャンペーンは2026年8月28日のリビジョン`27db0e1`で10レポートすべてに合格しました。中品質/CPU 4×のスケール検査はp95が9.3 ms、
  最悪フレームが66.5 ms、低品質/CPU 6×はp95が16.6〜16.7 ms、最悪フレームが83.4 msです。観測検査では
  両プロファイルとも木星を3/3で解像し、リソース数にドリフトはありません。

## 現在の優先事項

- アクティブな天体の祖先を天体ごとではなくフレームごとに一度計算し、
  ターゲットの優先順位とカタログの変更を維持します。親の欠落と循環もテスト済みです。
  CPU 6× の単独テスト（503 エントリ、200 更新）は 95.2–98.2 ms から 74.6–80.3 ms に短縮され、
  LOD 状態は一致します。カメラと描画規則は変更せず、アプリ全体の FPS 向上を示す測定ではありません。
  コールド計測は各プロファイル 3/3 合格（最大 low 66.8 ms / medium 100.0 ms）。
  Tempel の中央値は 27.0 / 31.2 ms ですが、medium の最大 78.2 ms は目標を超えています。
- 8K パノラマは解像度と色を維持したまま、GPU 転送前に非同期でデコードします。
  Chrome / CPU 6× の単独転送は 742.7–790.8 ms から 96.2–102.8 ms に短縮され、
  Chromium、Firefox、WebKit でサンプリングした GPU ピクセルは一致しました。
  遅れて読み込まれた場合も、テクスチャ破棄時にビットマップを解放します。
  初期プリウォームはシェーダーコンパイルと並行して任意のパノラマを最大 500 ms 待ち、
  通常のローカル転送が最初のナビゲーション中に発生するのを避けます。
  その他の GPU スパイクとクリーンな状態での全体計測は未完了です。
  最終コールド計測は low で 3/3、medium で 2/3 合格（最大 66.7 / 100.1 ms）です。
  100 ms の上限は変更していません。Tempel の中央値は 26.6 / 28.4 ms で、
  6 回すべての初回表示フレームが 33.3 ms 未満です。小規模なローカル計測であり、全体検証の代替ではありません。
- 9月11日の検索・ラベル改善後、低品質/CPU 6×と中品質/CPU 4×は対象検証で各3/3合格
  （最大100.0、99.9 ms）です。Tempel中央値は低品質33.7 ms（予算超過）、中品質32.6 msで、先読みは各3/3成功しました。
  全行程の最悪フレーム遅延は前回より改善していません。区間ごとの遅延ピークとクリーンなリビジョンでの
  全体検証は未完了で、過去の基準は置き換えません。
- Cosmicflowsのジオメトリと大規模構造のシンボルを、安定ソート・選択用インデックスを含めて小さな
  バッチに分割し、処理の合間にブラウザーへ制御を返します。完了後にまとめて反映し、中止時は資源を
  解放します。レジストリのID、位置、順位、検索名・別名もバッチ処理し、検索キャッシュが完成してから
  公開します。系外惑星のID、位置、軌道準備、主星順位、検索項目にも同じ方式を適用し、
  参照天体との対応と科学的な値を保持します。位置と見た目は変更していません。恒星タイルのID対応表と
  可視範囲もバッチ処理し、インデックスが完成してから公開します。Gaiaの全3,964セルと検証した378通りの
  ビューの結果は同一です。HYGの名前とラベルもバッチで準備し、キャッシュを再利用します。
  検索と系外惑星の発見一覧は両方が完成してから同時に公開し、準備中も以前の版を利用できます。
  データや言語の変更で古くなった処理は破棄します。科学的な値と結果の順序は変わりません。
  その他の恒星処理、GPUの初回処理、クリーンなリビジョンでの全体検証は引き続き対象です。
- 最初のCPU最適化を実装しました。選択マスクの差分更新、順位スコアの事前計算、検索キーワードの
  有界キャッシュです。カメラと描画は変更していません。対象を絞ったスケール移動は全行程の予算を
  満たしますが、コールド状態の各区間の遅延とクリーンなリビジョンでの再検証は未完了です。
  過去の10/10基準は置き換えません。
- 参照映像と比較して腕・核・内部通過の最終的な見た目を確認します。ブラウザーテストは視点、
  空間的安定性、銀河選択を検証しますが、技術的に見えることと見た目の承認は区別します。
- 9月10日のローカル診断で記録したフレーム予算超過を調査し、その後クリーンなリビジョンで
  キャンペーンを再実行します。上記10/10の値は8月28日の過去の基準で、現在の未コミット状態の
  合格を意味しません。シミュレーションは別の機器の証拠ではなく、中・低性能実機検証は任意です。

プラネタリウムは選択地点の独立した観測地点中心投影です。時間マップの受信した光は、対応する
太陽系天体には地球を、HYG恒星と文書化された系外惑星系には太陽系重心を使います。
